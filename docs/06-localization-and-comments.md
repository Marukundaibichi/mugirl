# 注释与本地化规则

本文件补充两条硬性规则：所有注释必须使用中文；所有玩家可见字符串必须使用翻译键。该规则适用于后续全部重构阶段。

## 中文注释规则

必须遵守：

- C#、XML patch 说明、文档内代码示例旁的源码注释，都必须使用中文。
- 必要注释应解释设计原因、兼容边界、状态生命周期、性能取舍、存档字段含义和数值保护原因。
- 英文注释、中英混杂注释、机器翻译腔注释必须在迁移文件时改成中文或删除。
- 允许在中文注释中保留 C# 类型名、Def 名、API 名、DLC/mod 名、Harmony 术语和翻译键。

禁止：

- 只复述赋值、返回、空判断的低价值注释。
- 保留过期 TODO、调试说明、个人备注、生成来源说明。
- 用注释掩盖命名不清；能通过类名、方法名、字段名表达的，应先改命名。

## 翻译键规则

不得在 C# 中硬编码中文或英文玩家文本。以下内容必须使用翻译键：

- 设置项名称和说明。
- Gizmo、FloatMenu、按钮、菜单、InspectString。
- Message、Letter、Mote 文本。
- DevMode 文本。
- 玩家能看到的错误、警告、诊断文本。
- 任务、事件、对话和描述文本。

Def XML 中的玩家可见字段必须使用 RimWorld 的 `DefInjected` 机制迁移：

- `label`、`description`、`jobString`、`reportString`、`verb`、`gerund` 等字段在源 Def 中使用对应注入键作占位。
- `Languages/*/DefInjected/<DefType>/*.xml` 必须补齐实际中英文文本。
- 自定义 comp 字段如果由 C# 调用 `.Translate()`，使用 `Keyed` 翻译键。
- 源 Def 中的注释仍按中文注释规则处理；语言文件中的实际翻译文本可以是中文或英文。

翻译键要求：

- 使用稳定前缀，例如 `MooGirl.Settings.*`、`MooGirl.Milk.*`、`MooGirl.Restraints.*`。
- 键名表达语义，不以当前中文或英文句子作为键名。
- 迁移硬编码文本时，语言文件中的中文翻译必须保持原显示含义。
- 文案含义变化属于玩家可见行为变化，必须先记录并确认。

例外：

- `defName`、Scribe 字段名、内部缓存 key、Harmony patch 诊断 key 可以硬编码，但必须不是玩家文本。
- 数值锁定文档中的历史字符串快照可以保留原文，用于对照旧行为。

## 迁移流程

迁移文件时按以下顺序处理：

1. 先列出该文件所有注释和硬编码字符串。
2. 删除低价值注释，保留必要注释并改为中文。
3. 判断每个字符串是否玩家可见。
4. 玩家可见字符串改为翻译键，并补语言文件。
5. Def 玩家字段改为 DefInjected 占位，并补对应语言文件。
6. 对比旧文本，确认含义未改变。
7. 编译并在 DevMode 下检查文本显示。
