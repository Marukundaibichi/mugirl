# 注释与本地化规则

本文件补充注释与本地化硬性规则。C# 玩家可见字符串必须使用翻译键；源 Def XML 使用英文原文，并在旁边用中文注释标注含义；中文翻译文件中的注释使用对应英文原文。该规则适用于后续全部重构阶段。

## 注释规则

必须遵守：

- C# 注释以中文说明设计原因、状态生命周期、性能边界和兼容风险；可保留 API、Def、DLC、mod、Harmony 等英文术语。
- 源 Def XML 的玩家可见字段必须写英文原文，并在相邻注释中直接写中文含义，不加 `中文：`、`CN:` 等前缀。
- 源 Def XML 的普通说明性注释应使用英文 + 中文对照，方便中英文维护者同时阅读。
- `Languages/ChineseSimplified` 中如需保留注释，注释必须写对应英文原文，不加 `EN:` 等前缀。
- 必要注释应解释设计原因、兼容边界、状态生命周期、性能取舍、存档字段含义和数值保护原因。
- 旧的 `EN:`、`中文：`、机器翻译腔注释必须在迁移文件时改成上述格式或删除。
- 允许在中文注释中保留 C# 类型名、Def 名、API 名、DLC/mod 名、Harmony 术语和翻译键。

禁止：

- 只复述赋值、返回、空判断的低价值注释。
- 保留过期 TODO、调试说明、个人备注、生成来源说明。
- 用注释掩盖命名不清；能通过类名、方法名、字段名表达的，应先改命名。

## 翻译键规则

不得在 C# 中硬编码中文或英文玩家文本。以下内容必须使用 Keyed 翻译键：

- 设置项名称和说明。
- Gizmo、FloatMenu、按钮、菜单、InspectString。
- Message、Letter、Mote 文本。
- DevMode 文本。
- 玩家能看到的错误、警告、诊断文本。
- 任务、事件、对话和描述文本。

Def XML 中的玩家可见字段必须使用 RimWorld 的 `DefInjected` 机制迁移，但源 XML 不写翻译键：

- `label`、`description`、`jobString`、`reportString`、`verb`、`gerund` 等字段在源 Def 中写英文原文。
- 源 Def 的相邻注释写中文含义，方便维护时对照；注释不加语言前缀。
- `Languages/*/DefInjected/<DefType>/*.xml` 必须补齐实际中英文文本。
- `Languages/ChineseSimplified` 的注释如果存在，写对应英文原文；节点正文写中文翻译。
- 自定义 comp 字段如果由 C# 显示，源 XML 同样写英文原文，语言文件用 `DefInjected` 注入实际翻译；C# 只在字段未由 XML 覆盖、仍使用默认 Keyed 值时翻译。
- C# 读取“可能来自 XML 实际文本、也可能来自默认翻译键”的字段时，必须使用统一解析方法，例如 `MooGirlText.Resolve`，避免把 XML 文本误当成 key 翻译。

翻译键要求：

- 使用稳定前缀，例如 `MooGirl.Settings.*`、`MooGirl.Milk.*`、`MooGirl.Restraints.*`。
- 键名表达语义，不以当前中文或英文句子作为键名。
- 迁移 C# 硬编码文本时，语言文件中的中文翻译必须保持原显示含义。
- 文案含义变化属于玩家可见行为变化，必须先记录并确认。

例外：

- `defName`、Scribe 字段名、内部缓存 key、Harmony patch 诊断 key 可以硬编码，但必须不是玩家文本。
- 数值锁定文档中的历史字符串快照可以保留原文，用于对照旧行为。

## 迁移流程

迁移文件时按以下顺序处理：

1. 先列出该文件所有注释和硬编码字符串。
2. 删除低价值注释，保留必要注释并改为当前文件类型要求的格式。
3. 判断每个字符串是否玩家可见。
4. C# 玩家可见字符串改为 Keyed 翻译键，并补语言文件。
5. 源 Def 玩家字段改为英文原文加中文注释，并补对应 DefInjected 语言文件。
6. 自定义 comp 字段由 C# 显示时，确认 C# 使用 `MooGirlText.Resolve` 或等价方法处理 XML 实际文本与默认 Keyed 值。
7. 对比旧文本，确认含义未改变。
8. 编译并在 DevMode 下检查文本显示。
