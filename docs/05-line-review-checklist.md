# 逐行审查清单

本清单用于保证“每一行代码都审查，不放过任何问题”。每个文件迁移前后都必须按此清单检查。

## 文件级记录

每个文件建立一条记录：

```text
文件路径：
所属模块：
当前职责：
目标职责：
是否保留：
是否拆分：
是否含数值：
是否含玩家可见行为：
是否含 Harmony patch：
是否含 Scribe 字段：
是否含 tick：
审查人：
审查日期：
结论：
```

## 通用代码审查

逐行检查：

- 类名是否表达唯一职责。
- 命名是否规范，是否存在拼写错误继续扩散。
- using 是否多余。
- 字段是否有明确所有者和生命周期。
- public 成员是否真的需要 public。
- null 检查是否合理。
- 错误处理是否吞异常或刷日志。
- 消息文本是否本地化。
- C# 玩家可见字符串是否全部使用翻译键；源 Def XML 玩家文本是否使用英文原文、中文注释和 DefInjected。
- 是否有硬编码 defName。
- 是否有硬编码数值。
- 是否有重复逻辑。
- 是否有注释与代码行为不一致。
- 是否缺少必要注释：状态机、tick、Harmony patch、反射、兼容层、存档字段、数值保护、非显然算法。
- 注释是否符合文件类型规则：C# 注释中文为主，源 Def XML 用英文 + 中文对照，中文翻译文件注释写英文原文。
- 是否存在低价值注释：只复述赋值/返回/空判断，或保留过期调试说明。
- 是否有中文临时注释、调试注释或过期注释。
- 是否有 `ToList()`、LINQ、全局扫描出现在热路径。
- 是否会影响非 MooGirl pawn。

## Harmony patch 审查

每个 patch 检查：

- 目标类型和方法是否正确。
- 注释是否说明为什么需要 patch、patch 边界和兼容风险。
- 游戏版本变化时是否容易失效。
- 是否有 `Prepare` 或模块启用条件。
- Prefix 是否阻断原方法。
- Postfix 是否只改目标场景。
- Transpiler 是否有明确 IL 匹配失败处理。
- 是否与其他 patch 顺序冲突。
- 是否访问私有字段或方法。
- 反射访问是否集中管理。
- 缺少 DLC 或第三方 mod 时是否静默跳过。

记录格式：

```text
Patch：
目标方法：
类型：
阻断原方法：
启用条件：
兼容风险：
替代方案：
是否保留：
```

## Tick 审查

每个 tick 方法检查：

- 为什么必须 tick。
- 注释是否说明 tick 频率、状态推进原因和性能边界。
- 执行频率是多少。
- 平均每次扫描多少对象。
- 是否查 DefDatabase。
- 是否分配 List、闭包、枚举器。
- 是否可改为事件。
- 是否可改为 hash interval。
- 是否可用 MapComponent 索引。
- 是否可能在暂停、世界地图、临时 pawn、销毁对象上运行。

记录格式：

```text
Tick 方法：
频率：
扫描范围：
分配风险：
替代方案：
保留理由：
```

## Scribe 审查

每个存档字段检查：

- 字段名是否语义稳定。
- 注释是否说明字段用途、默认值意义和是否允许旧档丢弃。
- 默认值是否正确。
- LookMode 是否正确。
- Pawn/Thing 引用是否可能失效。
- PostLoadInit 是否恢复缓存。
- 删除旧档兼容后是否还有无用字段。
- 静态状态是否错误地逃过存档。

## Def/XML 审查

每个 Def 检查：

- defName 是否符合命名规范。
- label/description 是否有语言文件。
- C# 中引用的显示文本是否都有翻译键；源 Def XML 是否使用英文原文、中文注释和 DefInjected，而不是翻译键占位。
- 是否有新增硬编码中文或英文玩家文本。
- class/thingClass/compClass 是否存在。
- texturePath/soundDef 是否存在。
- comps 参数是否被 C# 使用。
- 数值是否与基线一致。
- MayRequire 或兼容 patch 是否正确。
- 是否有重复 Def。
- 是否有旧档兼容残留。

## 模块专用审查

### Milk

- fullness 增长是否保持旧数值。
- 采集消耗是否保持旧数值。
- 哺乳、喝奶、喂奶是否都走统一消费规则。
- 设备接管满奶逻辑是否不会重复触发。
- 乳房 hediff 分类是否缓存。
- Gizmo、FloatMenu、Message、InspectString、DevMode 文本是否全部本地化。

### Restraints

- 锁状态是否只有一个权威来源。
- 装备移除时 hediff 是否清理。
- 破解/解锁是否正确消耗资源。
- 高级束具状态机是否可存档恢复。
- R18 内容是否保持常驻：不得恢复设置按钮、隐藏过滤、贸易库存剔除或地图/角色清理逻辑。
- XML 中的 `AdultContentExtension` / `CompProperties_AdultContentControl` 是否仅作为元数据和加载兼容外壳使用。

### Roping

- 牵引关系是否可查询、可清理、可存档或可重建。
- 绘制不扫描全图。
- 被牵引 pawn 死亡、消失、换地图时清理。
- 与骑乘互斥条件一致。

### Mounting

- 容器持有 pawn 的生命周期正确。
- 销毁、卸载、地图切换、下马失败都有兜底。
- `Verb.caster` 修改一定恢复。
- 静态缓存不会跨游戏残留。
- 绘制层级不影响非骑乘 pawn。

### Incidents

- 事件触发条件清晰。
- Pawn 生成后 faction、ideo、kind、apparel、backstory 一致。
- Quest signal 不丢失。
- 奖励和惩罚数值与基线一致。

## 完成标准

一个文件只有同时满足以下条件，才算完成：

- 已逐行阅读。
- 必要注释已补齐，低价值/过期注释已删除。
- 所有保留注释均符合当前文件类型规则。
- C# 玩家可见字符串均使用翻译键；源 Def XML 玩家文本均使用英文原文、中文注释和 DefInjected。
- 已决定保留、删除、拆分或重写。
- 已记录所有数值。
- 已记录所有玩家可见行为。
- 已消除或登记所有设计缺陷。
- 编译通过。
- 对应模块测试通过。
