# Wave S plan: module `milk` (Milk, Abilities, Xenotype, Appearance incl. Appearance/Apparel, AdvancedArmor)

Companion of `spec/milk.json` (Wave R renames). No `Mugirl.Features.Apparel` namespace is created: it would shadow `RimWorld.Apparel` in every `Mugirl.Features.*` file (CS0118); `MugirlApparelTagUtility` goes to Incidents as `Mugirl.Features.Incidents.KindApparelUtility` (incidents owns it in Wave S), and the incidents spec moves the 7 fixed-colour/pregnant-apparel types into `F/Appearance/Apparel/` (namespace `Mugirl.Features.Appearance`), which this module owns in Wave S (they contain no legacy code). Paths: `F/` = `Source/MugirlRace/Features/`, `D17/` = `1.7/Defs/`, `L17/` = `1.7/Languages/`.
Type names below are the **post-Wave-R** names from the spec (old name in brackets where useful). Line numbers are the 2026-10-15 tree.

### DOM steps (all idempotent, legacy session only, golden before/after tests in `Source/Tests/MugirlRace.Tests/SaveUpgrade/Milk/`)

1. **`XenotypeRepairComponentStep`** (runs before the global type pass; disposition `Consumed`). For each `game/components/li` whose `Class` is `Mugirl.Mugirl_XenotypeFix_GameComp` or `MooGirl.MooGirl_XenotypeFix_GameComp`: `pending = !(xenotypeFixed && throwGeneFixed && dunkGeneFixed && throwSystemGeneFixed)` (missing label = False, Scribe default); record `session.XenotypeRepairPending |= pending`; remove the `li`. A save without the element records nothing (every supported Mugirl-era build created it).
2. **`GatherDriverRelinkStep`** (after type/def renames). For each `<curDriver Class="Mugirl.Features.Milk.JobDriver_GatherMilk">` whose `curToilIndex` is `1` and which has **no** `gatherEffectsActive` child (1.6 never saved it; 1.7 always writes `True` once toil 1 ran): read the sibling `curJob/targetA` (`Thing_<id>`); add `<activeGatherTarget>Thing_<id></activeGatherTarget>`, `<gatherEffectsActive>True</gatherEffectsActive>`; if the target is not the gatherer, find the pawn element whose `<id>` is `<id>`; if its `jobs/curJob/def` is `Mugirl_MilkingTargetWait` and its `jobs/curJob/targetA` is `Thing_<gatherer id>`, add `<forcedWaitJobLoadId>` = that job's `loadID`. Result = exactly the shape a 1.7 save has, so the existing cleanup ends the target's wait job instead of leaving it waiting ≤15000 ticks. The three interaction drivers are **not** relinked: their partner wait expires after ≤560 ticks (`MugirlMilkInteractionUtility.cs:14-18`) and `Job_MugirlMilkInteractionWait` carries no target to verify ownership.
3. **`LactationBirthTickStep`**: in hediff `li` elements whose `def` (after DM) has `HediffComp_Lactation`: parse `lastBirthTick` with `double.Parse(…, NumberStyles.Float, InvariantCulture)`, write `lactationLastBirthTick` = `(int)Math.Round(v)` unless it equals `-1`; remove the old node.
4. **`ThrowLastFlightCellDefaultStep`**: for `<thing Class="Mugirl.Features.Abilities.ThrowController">` without `lastFlightCell`, add `<lastFlightCell>(0, 0, 0)</lastFlightCell>` (materialises the old Scribe default before the default changes to `IntVec3.Invalid`, S2-10).

### Post-load step

- **`XenotypeRepairPostLoad`** (phase C, gated by `session.XenotypeRepairPending` and `ModsConfig.BiotechActive`): for each `Pawn` in `PawnsFinder.All_AliveOrDead` with `def == Mugirl`, non-null `genes`, `!genes.UniqueXenotype` and no xenogenes, call the domain primitive `XenotypeUtility.EnsureMugirlXenotype(pawn, forceNonHybrid:false)` (set xenotype + add missing endogenes; the birth path uses the same primitive with `forceNonHybrid:true`). The eligibility filter (the legacy rule) lives only in the step. Same result as the deleted component's single scan (it ran 300 ticks after load; nothing in between depends on it). New games need nothing: every PawnKindDef that produces race `Mugirl` sets `xenotypeSet` `Mugirl_Xenotype` (via `Mugirl_BaseKind` `D17/PawnKindDefs/PawnKinds_Base.xml:10-25`, `CorporateServices.xml:55`, `PawnKinds_GiantCorp.xml` `AI_GC_MugirlRaider`; checked all 11 kinds), and newborns go through the birth patch.
