# Wave S plan — module `content`

Scope: content not owned by a feature module (see `content.json` `ownedContentFiles`), the shared `JobDefs.xml`,
global content-file naming, the 38 dead Keyed keys, the dead-content list (understand/content.md A.2), and the
MooGirl-era name tables. Repo root `R`; content paths are relative to `R`. All line numbers were re-read on
2026-10-15 in the working tree.

Some files were assigned to content but serve exactly one feature, and that feature's spec already claims them.
Content hands their Wave S ownership to that feature (S5-Q1):
- Milk/Apparel: `Apparel_PMC.xml`, `Items_Resource.xml`, `WorkGivers.xml`, `Mods/VCookE/**`, `Mods/Odyssey/**`, and the
  two trader-stock patches.
- Combat: `RangedWeaponsEnemy.xml` → `RangedWeapons_GiantCorp.xml`.
- Core: `MaterialDefs` and `ShaderDefs`.

The def renames for those files stay in `content.json`. They are identical to the sibling entries, except for one
conflict (S5-Q2).

Data files written next to this plan (all generated by scripts in `spec/work/content/`, reproducible):

### S2-4 MUST (verified defect) — race horn addon conditions
Files: `1.7/Defs/ThingDefs_Races/Mugirl_Race.xml:275-276` and
`1.7/Languages/ChineseSimplified/DefInjected/ThingDef/Mugirl_Race.xml:9-12`.
The `bodyAddons` order is 0 tail, 1 adult left horn, 2 baby left horn, 3 adult right horn, 4 baby right horn,
5 child left, 6 child right, 7 body accessory, 8 face accessory (parsed from the XML).

History (git): the DefInjected keys `bodyAddons.1/.2.conditions.1.bodyPartLabel` date from `d9b9bb9`, when the list
was [tail, left, right]. The baby layers were later inserted at index 2. Index 2 thus became the baby left horn, while
the translations stayed "right horn" (1.6 English DefInjected `1.6/Languages/English/DefInjected/ThingDef/Mugirl_Race.xml:7`)
and 右牛角. The unreleased 1.7 tree wrote that leftover into the XML (:276 `right horn`, comment :275).

Defect 1: the baby left horn is tied to the right horn.
Defect 2: HAR compares the condition string with `bpr.untranslatedCustomLabel` (decompiled `har16`
`AlienRace.ExtendedGraphics.ExtendedGraphicsPawnWrapper.IsBodyPart`), so a translated value (左牛角/右牛角) can never
match. It also differs from the part's own translation 左角 (`DefInjected/BodyDef/BodyDef.xml:20`).

Effect: every horn addon has `drawWithoutPart=true` (:236, :277, :317, :357, :397, :437), so the addons always draw.
The label only selects `ResolveData.bodyPart`, that is, which horn's damage/hediff graphics apply.
Fix: set :276 to `left horn` and delete :275. Delete the two DefInjected entries and their comment lines (the condition
value must stay the untranslated custom label).
`bodyAddons` must only ever grow at the end. Indices 0–4 existed at `324501c` and 5–8 were appended later, and HAR
saves `addonVariants` by index (design §2). Never reorder or insert.
Save impact: none.
Behaviour change: visible only when a horn is damaged or missing. This is a **defect fix**; record it.
Tests: validator `defValues` contract checks that every horn addon's `bodyPartLabel` equals its side, and that no
DefInjected key ends in `.bodyPartLabel`. In game (Wave V): a baby with the right horn removed draws the left horn
normally, in English and in Chinese.
Risk: low. HAR 1.7 should be re-checked; the local HAR (839005762) has no 1.7 folder.

## S5. Open questions (with proposed answers)

1. **File ownership overlaps with sibling specs.** Some files were assigned to content and also claimed by milk, combat
   and core. *Proposal:* content keeps the truly shared or feature-less files: `JobDefs.xml`, `MugirlPatch.xml`, race,
   body, backstories, traits, filth, research, scenario, lifestages, namegen, player faction/pawnkind,
   `Mods/SearchAndDestroy`. Each single-feature file goes to its feature: Milk/Apparel, combat (`RangedWeaponsEnemy.xml`),
   core (Material/Shader).
2. **Filth name**: milk proposes `MugirlMilkStain`→`Mugirl_MilkStain`; content proposes `Mugirl_Filth_MilkStain`.
   *Proposal:* use `Mugirl_Filth_*` for all three filth defs (`ShockMilk`, `MilkStain`, `ShockFluid`). This follows
   vanilla `Filth_*` and matches the `Mugirl_Mote_`/`Mugirl_Fleck_` names agreed with restraints.
3. **Projectile naming**: aligned with combat as `Bullet_Mugirl_<weapon>`, which keeps the 4 existing `Bullet_Mugirl_*`
   names. This deviates from design §3.3 (`Mugirl_` first). *Proposal:* accept it and list it as a §3.3 exception
   ("vanilla role prefix `Bullet_` + Mugirl weapon name").
4. **Element-level splits** (S2-1 JobDefs, S2-2 MugirlPatch, S2-3 Misc_Gameplay). *Proposal:* do them in Wave R as
   deterministic XML element moves from the tables here, so Wave S starts with single-owner files. Fallback: Wave S
   step 0 by content.
5. **`MooGirl_GiantCorporations`** (live hidden faction in S1/S2). *Proposal:* drop it with the remove-faction policy
   (L2), not map it to `Mugirl_GiantCorporations_Hostile`; mapping would turn a hidden neutral faction into a visible
