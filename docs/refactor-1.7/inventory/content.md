## 0. 结论速览

1. **def 集合与已发布版完全一致**：工坊发布版（3578882219，9/26，547 个 defName）中的每个 defName 在 1.7 中都存在；1.7 只多 6 个（`Mugirl_SlaveRefugeePodCrash`/`Mugirl_SlaveWandererJoins` 两个 IncidentDef、2 个 ShaderDef、2 个 MaterialDef）。1.6 工作区（冻结版）与 1.7 的差集同样只有这 4 个渲染 def。因此**当前 1.7 内容没有“已改名需要映射”的 defName**；统一升级器的 defName 映射表将完全来自本次重构的改名，外加下面 A.1 的两个退役 def 与 A.7 的历史 def（可选）。
2. **真正只为旧档存在的内容只有 2 处**：`IncidentDef Mugirl_WildManWandersIn`（`1.7/Defs/Compatibility/RetiredEvents.xml`）与 `PawnKindDef Mugirl_PreEscapeWildSlave`。另有一批**死内容**（1.6 起就无人生成/引用，不在任何存档里）可以直接删除，无需升级器参与（A.2）。
3. **存档里写着的“字符串”不只有 defName**：17 个 Keyed 键作为 `CorporateRecord.key` 写进存档（A.6.3）；DefInjected 键路径用 C# 类型短名作句柄（D.2，9 个 Mugirl 类）；`BodyDef MugirlBody` 以 defName+部位索引写入每个带部位的 Hediff（B.2）。
4. **外部依赖**：已支持 1.7 的工坊 mod `KindSeal.LOL`（3555662938）直接引用 C# 类 `Mugirl.StockGenerator_Mugirl_Slaves`、race defName `Mugirl`、mod 显示名 `Mugirl Race`；`Kindseal.UFPC`（3698316804，1.7）引用 `Job_Charge` 与贴图 `UI/Mugirl_Charge`。本机 1.6 衍生 mod（Subspecies、白绒物语）大量引用抽象 Name、`Mugirl.*` 类与 `MugirlBody`、`Mugirl_Body_bondage` 等（C 节）。
5. **命名问题集中在**：无前缀/异前缀的 JobDef（20 个 `Job_*`/`JobDriver_*`/无前缀）、`AI_GC_*` PawnKind、`PMC_*`/`OPC_*` 武器服装、`Mugirl*` 无下划线的 filth/fleck/mote/ThinkTree/Body、`Hediff_Mugirl*`/`Consumed_Mugirl*`、明显拼写错误 `Mugirl_Bar`（实为 Bra）、大小写不一 `Mugirl_Slaveboots`、`BrainWash`/`Brainwash` 混用、文件名带日期（`*_0920.xml`）。B.5 给出只针对明确错误的改名表。
6. 旁证发现（E 节）：6 个 def 中有同名字段重复（另有 PrefabDef 内 19 处待确认），1.7 `XmlInheritance.CheckForDuplicateNodes` 会对有父类的 def 报错 [反编译]，`FactionDef Mugirl_GiantCorporations_Hostile` 的配置错误在 1.7 仍在，About.xml 仍只声明 1.6（按迁移计划有意为之）。

### B.2 哪些 defName 写进存档（决定改名是否需要升级器）

已用反编译核实的：
- `BodyDef`：`Scribe_BodyParts.Look` 写 `<body>defName</body><index>部位索引</index>`（rw17 `Verse.Scribe_BodyParts.Look`）。所以 **`MugirlBody` 改名要映射，且 `1.7/Defs/Bodies/BodyDef.xml` 的部位树顺序一改，旧档所有带部位的 Hediff（伤口、义体、束具 Hediff 的 `HediffTargetBodyPartDefs`）都会错位**，必须让升级器按“旧索引→部位路径→新索引”重映射或冻结部位树。
- `JobDef`/`JobDriver`：`Pawn_JobTracker.ExposeData` `Scribe_Deep(curDriver)`、`Scribe_Deep(curJob)`、`jobQueue`（rw17 `Verse.AI.Pawn_JobTracker.ExposeData`）。curJob 存 `def`、`workGiverDef`。找不到 driver 类时原版 “Cleaning up invalid job state” 并结束工作（同方法）。
- `ThingFilter`：`allowedDefs`（ThingDef 列表）与 `overrideRootDef`（rw17 `Verse.ThingFilter.ExposeData`）——所有物品 defName 出现在储存区、服装/食物方针、订单原料过滤里。
- FA 类型 def：`FacialAnimation.ControllerBaseComp.PostExposeData` 写 `Scribe_Defs.Look(ref faceType, GetType().Name + "_faceType")`（FA 1.6 DLL），即 `Mugirl_HeadNormal*`、`Mugirl_EyeNormal*`、`Mugirl_LidNormal*`、`Mugirl_BrowNormal*`、`Mugirl_MouthNormal*`、`Mugirl_LidOptionNormal*`、`Mugirl_EmotionNormal*` 存档可见。
- 尘埃/Mote：原版 `MoteBase` `isSaveable false`（`Data/Core/Defs/Effects/Mote_Visual.xml:17`），`MugirlWashMentalEyesInHead` 不进存档；Filth（`BaseFilth`）进存档。

按原版标准行为（未逐一反编译）存档可见的类型：ThingDef（物品、服装、武器、建筑、filth、种族、弹头、PawnFlyer；**含隐含 def**：`Make_<ThingDef>` 配方、`Blueprint_<X>`/`Blueprint_Install_<X>`/`Frame_<X>`、`Corpse_<race>`）、PawnKindDef、FactionDef、HediffDef、ThoughtDef（记忆）、TraitDef、BackstoryDef、HairDef、HeadTypeDef、GeneDef、XenotypeDef、AbilityDef、ResearchProjectDef（进度字典键）、RecipeDef（订单）、JobDef、WorkGiverDef（`Job.workGiverDef`）、QuestScriptDef（`Quest.root`）、IncidentDef（`StoryState` 触发记录、事件队列）、SitePartDef、DutyDef（`PawnDuty.def`）、TraderKindDef（商船/商队）、InteractionDef（PlayLog）、MentalStateDef（当前精神状态）、PipeSystem.ProcessDef（VEF 处理器的进行中工序）。

### B.3 建议的约定

1. 所有 def（含抽象 Name）以 `Mugirl_` 开头，后接 PascalCase；不在 defName 中重复类型（禁止 `Job_`、`JobDriver_`、`Hediff_`、`Work_`、`Consumed_` 等），类型由 DefDatabase 区分。同一概念跨类型可同名（如 IncidentDef=QuestScriptDef、AbilityDef=GeneDef=HediffDef `Mugirl_Charge`、束具 SlaveApparelDef=其 equipped HediffDef），不同概念不可同名（现 `Mugirl_Stocking`、`Mugirl_Underwear`、`Mugirl_Slave` 违反）。
2. 系列/分组用第二段：`Mugirl_GiantCorp_<Role>`、`Mugirl_PMC_<Item>`、`Mugirl_Bullet_<Weapon>`（或保留原版习惯 `Bullet_Mugirl_<Weapon>`，二选一全局统一）、`Mugirl_Filth_<X>`、`Mugirl_Mote_<X>`/`Mugirl_Fleck_<X>`。
3. 抽象 Name 一律 `Mugirl_<X>Base`。
4. 禁止日期、版本号、资源编号、拼音（品名除外需注明）进入 defName、Name 与文件名；文件按 Def 类型/功能命名，DefInjected 文件名与 Defs 文件名一一对应。
5. 例外（显式写入 README）：种族 `Mugirl`；FA ShapeDef 通用名；FA FaceAnimationDef 的 `<FA名>_Mugirl` 后缀；`BodyPartGroupDef Ears`（B.6）。
