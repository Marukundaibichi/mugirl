# 外部任务来源键导致 ThinkTreeKeys 迁移失败

## 原因与证据

本次报告与 1016.1 修复的奶量字段冲突不同。玩家备份 `渡鸦流亡者2.rws.mugirl-schema0.bak` 为 16,422,014 字节，SHA-256 为 `8D8A51A1D88E9DE98C03218B8FC369D4B669A0F0F1F0C68FAE005AF2FCF2C286`。它没有 `milkFullness`，保存版本为 1.7.4977 rev1248，包含 221 个模组标识和 38 条带来源键的 Job。

日志在 1.7.4980 rev60 下报告 `No single captured ThinkTree layout proves all saved Job keys.`。38 条来源包括 Animal 的漫游、Mechanoid 的 LayDown，以及 Humanlike 的 AttackMelee/Wait_Downed。原代码把所有键都作为雪牛娘历史布局的约束，一个不属于可识别旧键空间的外部来源便清空全局候选，整次升级失败。

通过 DecompilerServer 核实 4980 的 `Job.ExposeData`：Saving 会把空 jobGiver 的键改成 -1，并因默认值省略标签；单纯放过原版的未知键会在下次保存丢失原整数。`Job.Clone` 不复制这个私有字段，`Job.Clear` 也不清空它。因此本修复同时处理来源保留、复制和对象池回收，不能仅取消失败判断。

## 改动

- 仅将归属明确为外部、所有历史账本和当前树均不存在的键交回原版。雪牛娘所属、归属未知、跨树、已捕获布局冲突、当前节点冒充旧来源等仍失败。
- 对真实主存档 Job 的实际原版查找失败记录原键；保存时不修改任务，只补写原版会省略的原始编号。记录按 Job 弱引用保存，并核对树、Def、loadID 和空来源。
- Clone 显式续接，Clear 清理；找到来源或身份改变时旧记录失效。支持当前 schema 再读，不对侧文档、无本模组文件或更新 schema 登记。
- 新增三个必需补丁入口：`Job.ExposeData` Postfix、`Job.Clone` Postfix、`Job.Clear` Postfix。安装检查和补丁基线同步更新；其余基线没有语义改动。
- 写出协议只在已核验的 4980 MVID 启用；不把未知键映射为任意节点，不重置或结束任务，不修改 JobDriver 状态，不隐藏原版警告，也不增加保存标签。
