# 同名奶量字段导致旧档迁移失败：修复与验证

## 问题与来源

玩家提供的 `瓦尔基里.rws.mugirl-schema0.bak` 为 41,729,729 字节，SHA-256 为 `A65DF92C52F612A99143D3BEFC43D20655E8F899C7D2AD234B9245C957EAF5CF`。日志在 `Framework.Labels` 报不能把 `milkFullness` 改为已存在的 `mugirlMilkFullness`。

原文件实际没有新标签。20 个对象各有两个旧标签，其中 16 个为雪牛娘；这 16 对中 12 对的值不同。旧通用标签步骤把同一 Pawn 的两个字段都认作雪牛娘字段，第二次计划改名时撞到第一份计划的目标名称，因此失败。原版只读语料复验在同一步失败，先前类型步骤完成 41 项改名。日志确认 Equal Milking 已加载，但本次没有玩家对应的 DLL，不把第二份字段的具体写入类型作为已确认事实。

旧 `Mugirl.CompMooHasBodyResource.PostExposeData` 已通过 DecompilerServer 核实：先写奶量，再连续写满值通知、通知时刻、结算时刻和阈值，默认值可省略。核验的是冻结 DLL，MVID `58f3a3709062448c84d0cf379b1f76c4`，方法 `0600030A`。本轮没有修改它。

## 修复边界

- 新增 `SaveUpgrade/Modules/Milk/MilkProductionLabelsStep.cs`，将这组标签由普通改名改为 `Milk.ProductionLabels` 明确消费；位于既有 `Milk.ResourceAccrual` 之前。
- 依据连续、唯一的旧私有状态区块认领其紧邻的奶量，仅给本组件的字段改名；其余同名节点保持对象身份、文本值与相对次序。
- 私有状态存在而本区块没有奶量时，保留旧默认零，不能取另一组件的奶量代替。已有当前组件状态时，不再认领外部旧字段，保证无版本戳的离线第二次升级也不变。
- 单一旧奶量且没有其他奶量控制字段时保留已有迁移契约；多个无私有状态佐证的旧字段、已知外部控制字段造成的单值歧义、重复/分裂私有状态和新旧私有状态混杂仍失败。
- 原 `Framework.Labels` 的冲突检查不放宽，领域组件和公开 API 不改。金样只包含本组件的合成字段；双组件共存、顺序颠倒、同值/异值、默认零与失败保护由专门回归测试覆盖。
